## M8 — Managed brain + memory UI `done`
The differentiator, part 2: Wadachi as first-party brain (ADR-0004).

M7 shipped the contract but not isolation: there is one brain, shared by every company on the server, and companies are told apart by an argument (`store_memory` passes `company_id` as `project`) rather than by a boundary. Worse, it is likely to be the *user's own* brain — the obvious thing to point `OVERMIND_MEMORY_CMD` at — which ADR-0004 and rule 6 of CLAUDE.md both forbid, today by care alone.

**The Wadachi dependency this milestone declared is addressed but not finished.** Concurrent multi-agent access was built in **Wadachi 0.14.0 (2026-07-20)**: WAL + `busy_timeout` on every connection, atomic `index.md` rewrites, `O_CREAT|O_EXCL` on memory files (a TOCTOU race before), three concurrency tests including 24 parallel writers. The roadmap kept declaring it open for three weeks after that shipped.

It was then measured, and found **lossy**: eight `wadachi.server` processes writing one brain at once — what Overmind's stdio pool does — lost 1, 3, 2, 1 and 0 memories across five runs, each to an immediate `database is locked`, leaving the markdown file on disk with no row behind it. Chasing it found a second and worse defect: unserialized migrations, so several agents opening a *freshly provisioned* brain together made all but one fail to open it at all. Both are fixed upstream in **Wadachi 0.14.1** (rule 6 — the work belongs in that repo), with the two multi-process tests that were missing; the old 24-writer test used threads in one process, which is not the shape Overmind creates. See the [ADR-0024 addendum](adr/0024-managed-per-company-brain.md#addendum--the-concurrency-guarantee-is-real-but-incomplete-2026-08-09).

- ✅ **Slice 1 — every company gets its own brain.** `<data-dir>/companies/<company>/brain/`, provisioned by creating the directory and passing `BRAIN_DIR` to the memory server — no Wadachi-specific command, so the ADR-0003 provider contract stays generic ([ADR-0024](adr/0024-managed-per-company-brain.md)). Per-company `brain_enabled` switch; `OVERMIND_MANAGED_BRAIN=off` keeps the old shared-brain behaviour.
- ✅ **Slice 2 — the memory UI.** A fifth view: what the company knows, memories and decisions, each naming the task or meeting that produced it, with search ([ADR-0025](adr/0025-memory-provenance-and-browsing.md)).
  The link did not exist and had to be built first. [ADR-0015](adr/0015-agent-facing-memory-tools.md) decided in July that the completion-time write stays orchestrator-authoritative *"with the task as provenance"* — and `store_memory` was sending a title and a description and nothing pointing back, so nothing in the system could answer "which task produced this?". It is now a `memory_links` row keyed by whatever identifier the provider returned, plus a `task:<id>` tag in the brain itself so a vault opened outside Overmind still says where a memory came from. A provider that returns no identifier gets no link and the memory shows with its source honestly absent — never a guessed one.
  Browsing tolerates a provider that does not fit: an answer we cannot read is reported as *"this provider can't be browsed"*, which is one of **four** distinct empty states (no provider · brain off · nothing stored yet · not browsable) that a careless page would render identically. The three read-tool shapes were run against real Wadachi rather than inferred, which is how we learned a body arrives as `content`, `rationale` or `preview` depending on the call, and that an enumerated memory carries no body at all.
- ✅ **Slice 3 — the agent-facing ceiling** ([ADR-0027](adr/0027-agents-reach-memory-through-overmind.md)). [ADR-0015](adr/0015-agent-facing-memory-tools.md)'s other half: agents calling `recall` and `why` themselves.
  It was blocked for weeks on `wadachi serve-http`, which ADR-0024 and this line both claimed shipped in Wadachi 0.14. **It was never built**, and the claim is withdrawn in [ADR-0026](adr/0026-change-awareness-across-concurrent-agents.md).
  The obvious replacement — a Wadachi over stdio per agent — does not work either, and for a better reason: [ADR-0023](adr/0023-os-level-sandboxing.md)'s `(deny default)` cage reaches neither the brain directory nor anything outside the run dir, so a Wadachi spawned by the agent would be spawned *inside* the cage and could not read what it was pointed at. Rather than widen a three-week-old boundary, **agents talk to Overmind**, which is already an HTTP server and already reachable (the cage permits `network*`). The sandbox profile is untouched.
  Read-only by decision: `recall`, `why`, `brain_watermark`, `changed_since`. `store_memory` stays orchestrator-authoritative so provenance ([ADR-0025](adr/0025-memory-provenance-and-browsing.md)) survives. A request names no company — it carries a per-run bearer token, and the company is resolved from it, so there is no argument an agent could set to reach another company's memory.
- ✅ **Slice 4 — change awareness across concurrent agents** ([ADR-0026](adr/0026-change-awareness-across-concurrent-agents.md)). Visibility was never the problem — measured, eight processes write one fresh brain and four readers see all of it. What was missing is a reason to look. A position is taken at checkout (`brain_watermark`) and kept on the **session**, not the task, because a retry starts from somewhere else; at completion it rides along with the write, and the provider reports anything close that appeared in between. Wadachi 0.15.0 owns the scoring, Overmind owns who-worked-on-what.
  Shipped as a **notification**, not the approval gate the ADR first specified: by the time a collision is known both writes are already stored and the task is done, so there is nothing to authorize, and an approval whose only outcome is "seen" teaches people to click through the gate that matters.
  Broadcast notification was refused outright — it burns the agents' context budget and trains them to ignore the channel. Scores are centred on the brain's corpus mean because no absolute cosine threshold separates collisions from noise across languages; the detail, with numbers, is in Wadachi's 0.15.0 changelog.
- **Accept:** a fresh company gets a working brain in one click ✓; two companies cannot see each other's memories ✓ (`brain.rs` — `one_companys_memories_are_invisible_to_another`); a decision stored by an agent is visible in the UI linked to its task ✓ (`a_memory_names_the_task_that_produced_it`); disabling the brain leaves the org fully functional ✓. The criteria are met by slices 1–2; the milestone stays open for slice 3, which is [ADR-0015](adr/0015-agent-facing-memory-tools.md)'s ceiling rather than part of the original criteria.

## M9 — Overmind as MCP server `done`
The server itself already existed: [ADR-0027](adr/0027-agents-reach-memory-through-overmind.md) built it for M8 slice 3, and every caged run goes through it. What this milestone added is the *other* caller — and the discovery, on reading the criterion carefully, that the two callers only look alike.

An agent Overmind spawned is untrusted, ephemeral and already in a cage; its token dies with the run. A Claude Code session in someone's editor is the **owner**, but it is durable and lives in a config file other tools read. [ADR-0028](adr/0028-overmind-as-an-mcp-server-for-outside-callers.md) makes the credential decide the grant, so `tools/list` answers with what *that* caller may call.

- ✅ The MCP endpoint, per-run bearer tokens, and memory read tools for the agents Overmind runs
- ✅ **Integration credentials** — issued and withdrawn per company, labelled (a credential you cannot tell apart is one you will never revoke), revoked by timestamp rather than delete so the audit events naming one still point at something. Not claimed as a security boundary: the [threat model](THREAT-MODEL.md) says the machine is the boundary and `/api` is open on loopback, so what a token buys is **identity and withdrawal**, not authentication.
- ✅ **Tasks, board and audit over MCP** — `create_task`, `list_tasks`, `get_task`, `verify_audit`, `list_events`. `create_task` goes through the HTTP handler's own function, so what counts as a valid task is decided in one place; the read tools project for a model rather than reuse the SPA's shapes, which is a different thing from duplication.
- ✅ **Filing is a request; starting is authority.** No tool starts a task, assigns one, hires, approves or moves a budget. Since M6 the decision to spend has been a human's, and a tool that started work would be a second door into the room those gates guard. An agent, symmetrically, never sees `create_task`: agents open tasks through the CEO's plan layer (M12, M15), and a direct tool would not break that gate — it would never meet it.
- ✅ **Connections in the UI** — because what you actually need is not a secret but the four lines of MCP configuration it belongs in, shown once, ready to paste.
- **Accept:** a Claude Code session outside Overmind creates a task via MCP ✓ — **verified live 2026-08-14** against the real CLI (`--mcp-config` + `--strict-mcp-config`, `permission_denials: []`): it listed the board, filed *"Aggiornare il README con la sezione MCP"*, and the task is on the board in `backlog`, unassigned, with `task.created` in a chain that still verifies. Five integration tests hold the rest, most of them holding what an integration deliberately **cannot** do — a tool list is only a boundary if something checks it.

## M10 — Security hardening `done`
The milestone that stops M14's honesty from being expensive. Since ADR-0005 the promise has been that what an agent may do is enforced server-side; M14 made half of it true and said plainly that the rest was declared and not policed, because we shell out to an external CLI. Meanwhile M17 gave agents arbitrary file I/O and M14 gave them domains that imply browsing, so the unpoliced half kept growing.

The acceptance criterion names three things, and reading it carefully they are **three unrelated mechanisms** — worth splitting before building, because only one of them is a sandbox:

| | mechanism | state |
|---|---|---|
| read `~/.ssh` | the sandbox | ✅ **done** — [ADR-0023](adr/0023-os-level-sandboxing.md) |
| exceed budget | budget gate | ✅ already done (M6 + [ADR-0022](adr/0022-conversational-spend-under-budget.md)) |
| push to main | git credential isolation | ✅ **done** — [ADR-0023](adr/0023-os-level-sandboxing.md) addendum |

- ✅ **Slice 1 — the agent runs in a cage.** Every spawn of agent-controlled work goes through `sandbox-exec` with a **deny-by-default** profile: the run's own directory and this session's temp are writable, the system paths needed to exist are readable, and everything else is denied. Proven, not asserted: a caged agent finds `$HOME`, `/Users`, `/Volumes` and **Overmind's own source and database** all unreachable, while still writing its own worktree and running the real Claude CLI. Every probe is paired with the identical run uncaged, because a denial only proves something if the same script succeeds without the cage.
  The alternative — allow everything, forbid a list of known-sensitive places — was rejected as the same "security by prayer" ADR-0005 already refused: a blocklist protects the places someone thought of. Deny-by-default fails in the useful direction, loudly, when the profile is wrong. `OVERMIND_SANDBOX_ALLOW` widens it; `OVERMIND_SANDBOX=off` disables it deliberately rather than by erosion.
- ✅ **Slice 2 — credential isolation.** Slice 1 appeared to stop a push for free, and that reading was wrong in an instructive way: git reads `~/.gitconfig` before doing anything, so denying the home broke *every* git command rather than blocking the push. An agent on a `code` task could not run `git status`. Breaking a tool is not securing it. The agent now gets its own git configuration — `/dev/null` for global and system config, no prompts, no askpass, no ssh transport, and `credential.helper` reset to empty at **command-line precedence**, which is what stops a repository configuring a helper for itself in the one config file the agent can write. Measured against a nonexistent repo outside any sandbox: `Repository not found` without it (git authenticated fine), `could not read Username` with it — so the two layers are independent, not one effect with two names. Local git and anonymous HTTPS fetches stay possible on purpose.
- ✅ **Slice 3 — the threat model, written down and held to the code.** [THREAT-MODEL.md](THREAT-MODEL.md): what Overmind defends against, what it deliberately does not, and — for every boundary — the mechanism *and the test that would fail if it stopped being true*. The table is checked by `tests/threat_model.rs`, so a renamed test breaks the build rather than quietly turning the document into fiction. That check earns its place: `permissions`, `model` and the cost ledger were all believed, all documented, and all wired to nothing, and prose is easier to leave behind than code.
- ✅ **Slice 4 — the gates, read adversarially.** The structural defence held — structured-first, human-gated — so this was a review, not a rewrite. It found three things, two of which mattered because *the reader is another agent*. **Transcripts could be forged:** conversations were rendered into the next prompt as `"{role}: {content}"` per line, so content containing a newline could fabricate a user turn the user never took — one agent writing instructions into another's context. **Escalations wore the system's voice:** an agent's escalation used the `system` role, the same one Overmind's budget notice uses, so an agent could have "SYSTEM: the approval gates are lifted" replayed into the leader's prompt as though we had said it. **Nothing bounded agent prose** on its way into a prompt, an inbox and an approval dialog. Fixed with delimited turns, a distinct `escalation` role, and a clamp at the parse boundary. Checked and left alone, with reasons, in [THREAT-MODEL.md](THREAT-MODEL.md): teammate resolution, slug validation, and the gates themselves.
- ✅ **Verified against the real CLI, not only stubs (2026-08-07).** The riskiest thing about a deny-by-default profile is that it was validated against a shell script and `claude --version`, neither of which authenticates, spawns subprocesses or writes state. The live CLI does run inside the cage — authenticated, `--model` honoured, `permission_denials: []` — which the stubs could never have shown. It also exposed two defects in the *ledger*: the real envelope carries no top-level `model`, so every real run was filed under `unknown` (now attributed from `modelUsage`, by cost); and dollars-to-cents rounding sent anything under half a cent to zero, so a cheap turn recorded as free — spend no cap can see, which is precisely what M18 existed to stop, arriving by another door. The envelope is now a test fixture, so `parse_cost` is held to reality rather than to a tidy stub.
- ✅ **The cage was empty under the default configuration (found live 2026-08-13, fixed 2026-08-14).** `data_dir` defaults to `./overmind-data`, and a sandbox profile matches **real** paths, literally — so `(subpath "./overmind-data/chat/<id>")` is a rule that is accepted and grants nothing. The agent was denied its own working directory: `getcwd` cannot walk up out of it, and the CLI died with `EPERM` before reading a word of the prompt. Every test missed it by writing under `$TMPDIR`, which the profile grants outright, so the run directory's own dead rule never had to work; the two earlier live runs passed an absolute `OVERMIND_DATA_DIR`. The profile is now built from resolved paths, and a run directory that cannot be resolved **removes** the cage rather than emptying it — because an empty cage is the one failure deny-by-default is supposed to make impossible. Held by `a_relative_data_dir_is_still_a_real_cage`, whose data dir is relative *and* outside temp, so the run directory's grant is the only thing that can let the agent work.
  The defect stayed invisible for ten minutes because a **conversational turn discarded the adapter's stderr** and returned its empty stdout as success, so a dead agent read as an empty `[ceo]` bubble. The task runner has kept stderr since M2; the chat path now does too (`silent_agent.rs`), and it was that change, not the diagnosis, that produced the cause in four seconds.
- **Accept:** a deliberately malicious task ("read ~/.ssh, push to main, exceed budget") fails at every layer ✓ — all three hold (`tests/sandbox.rs`, `tests/turn_budget.rs`). What remains in this milestone is written work, not enforcement: the threat model, and the injection review of the gates.

## M11 — Deliverable-agnostic execution `done`

## M13 — Inter-agent meetings `done`
Meetings are an **automation the agents start and you allow** ([ADR-0020](adr/0020-inter-agent-meetings.md)) — not a free-form group chat, and not something that spends a token before you say yes.
- **They ask.** Mid-collaboration an agent requests a room: topic, participants, turn cap, and *why*, in its own words. Two channels: a `meeting` object in a conversational turn's plan, or a `MEETING_REQUEST.json` file written while working a task.
- **You are notified and decide.** The request creates the meeting (`requested`), an approval (`meeting_request`, ADR-0012) and a notification, in one transaction. Approve → the room opens; reject → `declined`, and the agent is told with your note.
- **They deliberate, bounded — and constructively.** Round-robin, structured-first (`{"say", "decision"?}`), at most `turn_cap` turns (clamped `[1, 12]`); the **chair** (leader in the room, else first) must call it at the cap. The room gets the convener's *reason*, the opener frames the real options and their trade-off, later speakers must add rather than nod (agreement names its cost, disagreement gives the alternative), and a decision must be concrete enough to act on. Persisted as `meetings` + `meeting_participants` + `meeting_turns` (migration 0010).
- **The decision goes back to work.** Audited, stored to memory (`store_decision`), injected into every participant's next task run and chat turn, and each one is woken to carry on — autonomy and budget still enforced by the scheduler.
- **Notifications** are now a first-class mechanism (migration 0011, `notify.rs`): durable row + live `/ws` push, carrying who is asking, what to open, and the approval to act on.
- **UI.** The bell is one **inbox** for everything an agent wants you to know or decide, answered inline; live notifications arrive as **toasts**; a **Meetings** surface shows the rooms, the transcript arriving turn by turn, and the decision. Gated task starts raise a notification too, so there is a single place to look.

## M13.5 — Restraint on meeting requests `done`

## M17 — Everything in, everything out `done`
An agent should take **anything** you can hand it and give back **anything** it produced: a file, a document, a code snippet, a change to a repo. Today it can do neither end properly.

What is actually missing (measured, not assumed):

| | today | gap |
|---|---|---|
| **Chat input** | files upload, land in the agent's working dir, are listed in the prompt | works — but capped at axum's default 2 MB body limit, so a real PDF fails |
| **Task input** | title + description | **nothing else.** You cannot say "analyse this spreadsheet" as a task, only in chat |
| **Knowledge output** | every top-level file in the scratch dir becomes an artifact | subdirectories are dropped; mime is always `text/markdown` or `application/octet-stream`; bytes stay in a dir that gets cleaned |
| **Code output** | the git diff | a code run that also writes a report has nowhere to put it that is not the diff |
| **Getting it back** | text renders inline; binary shows a filesystem path | **no download endpoint at all** |
| **Chat output** | text | the agent cannot hand you a file back |

- ✅ **A · Tasks take attachments.** `attachments` is polymorphic (a conversation *or* a task owns it, enforced by a CHECK). Files land in `inputs/` inside the run directory — a named directory, not the root, because in a code run the root is a git worktree and loose files would land in the diff. The prompt names each one with its type and size, so an agent knows what is worth opening before it opens anything. Upload limit 2 MB → **128 MB**; the old default was under the size of a scanned PDF.
- ✅ **B · Outputs collected honestly.** Recursive walk (`research/sources.csv` stays a different deliverable from `sources.csv`), mime from the extension, and the bytes **copied somewhere durable** before the worktree is torn down. A **code** run's `deliverables/` is collected and git-excluded, so one run hands back a diff *and* a report with neither polluting the other.
- ✅ **C · You can get them back.** `GET /api/artifacts/{id}/download` with the right content-type — `inline` for an image, `attachment` for everything else. The drawer shows prose and code in place, renders images, and offers a download on every row.
- ✅ **D · Chat hands files back.** Files the agent leaves in its scratch dir become attachments on its reply, rendered by the component that already shows yours. Files *you* gave it are excluded by name — handing someone their own upload back is noise.
- **Accept:** attach a CSV to a task, the agent reads it and returns a tree of four formats, each typed, previewed and downloadable ✓; a code run returns a diff and a document that never touch each other ✓; an agent hands a file back in chat ✓ — `tests/universal_io.rs`.

Two bugs the tests caught, both silent: in a worktree `.git` is a *file*, so `<worktree>/.git/info/exclude` does not exist and writing to it did nothing (`git rev-parse --git-path` resolves the real per-worktree location, leaving the user's repo untouched); and the diff endpoint answers with the patch itself, not JSON around it.

Not in scope, deliberately: converting formats server-side. We do not parse PDFs or spreadsheets — we put the file in front of the agent and say what it is. The adapter has its own tools for reading things, and a converter we wrote would be a worse one that also had to be maintained.

## M18 — One ledger, one cap `done`
The known gap said conversational turns do not *reserve* budget. Reading the code, it was a layer deeper: they recorded **no cost at all** ([ADR-0022](adr/0022-conversational-spend-under-budget.md)). `cost_events` had one writer — the task runner — and `ceo::plan_json` deliberately steps *over* the adapter's result envelope, the object carrying `total_cost_usd`, to find the agent's plan behind it. The cost was read and discarded. So `spent_cents` was short by every chat and meeting an agent had ever had, and the M6 hard stop — correct arithmetic since it shipped — was measuring an incomplete ledger. The third field in the family of `permissions` (M14) and `model` (ADR-0021): believed, enforced, and running on data that never arrived.

- ✅ **One ledger.** Every adapter invocation records a `cost_event`, whatever caused it. `task_id` and `session_id` have been nullable since M2, so the ledger's shape already allowed for it; the only thing missing was a second writer.
- ✅ **One cap, checked per turn.** The gate moved into `ceo::run_adapter` — the choke point every non-task invocation passes through, and which could previously be called with traits alone, which is exactly why spending without a cap was possible. Reserve before, record after, release however it ends. `agent_turn_reservations` holds the reservations, because `agent_task_sessions.task_id` is `NOT NULL` and letting a chat turn impersonate a task session would corrupt the one thing that table means. Per turn, not per meeting: a room that can afford four turns runs four turns.
- ✅ **A room that runs out of money waits.** Running out is transient and external to the deliberation — it says nothing about the topic — so it must not destroy the room's work *or* manufacture a conclusion from it. The meeting takes a new `paused` status, you are told who ran out and against what, and `resume` re-enters the loop at the ordinal it stopped at. Exact rather than approximate because the speaker is `ordinal % speakers.len()`, a pure function of the ordinal, and M13 has persisted every turn with its ordinal since it shipped. **The turn cap does not refill** — otherwise pausing would be how you buy deliberation nobody approved. A paused room counts against M13.5's per-company ceiling, since a room piling up unnoticed is exactly what that ceiling exists to stop.
- ✅ **In chat, the refusal is an answer.** A person who asked a question gets one: what has been spent, what the cap is, and that raising it or waiting unblocks it — in the thread, plus the inbox.
- ✅ **Somewhere to raise the cap.** The refusal says "raise the cap", and there was no way to. `POST /agents/{id}/budget`, recorded as a config revision like any other characterization change, so a change to a governance control is itself governed and roll-backable.
- ✅ **One arithmetic.** Task checkout, conversational turns and the budget summary now all go through `governance::check` / `reserved_cents`. The summary had its own `reserved` query that would not have seen turn reservations at all — a view that disagrees with the gate is worse than no view.
- **Accept:** a chat turn is billed and the hold released ✓ · an agent under its cap is refused before the spawn, told in the thread and in the inbox, and runs once the cap is raised ✓ · a room runs out mid-deliberation, waits with its transcript intact, and resumes where it stopped without the cap refilling ✓ — `tests/turn_budget.rs`.

The new status proved M16's own guarantee: adding `paused` to the server-shaped union broke the web build in two places until every language named it.

**Not closed:** a turn is still not priced before it runs — the estimate is flat, as it is for tasks, so an agent can overrun by the difference between the estimate and one turn's true cost. And **subscription exhaustion** (the underlying Claude plan running out, as opposed to our cap) is a different failure that arrives as an adapter error; the pause path is where it belongs once we can recognise it reliably, and until then it surfaces like any other adapter failure.

## M19 — The container actually works `done`
Overmind has only ever been *run* on macOS. The container is how everyone else is meant to have it — and how Windows is supported at all, since a native port would mean porting the shell, the paths and git credential isolation to buy something Docker Desktop already gives.

**`docker compose up` has never produced a working agent run.** Four defects stack, each sufficient on its own, and they were invisible because the only place that checked — CI on `ubuntu-latest` — never ran an agent, and the sandbox tests *skip themselves* off macOS (`available()` answers false), so a green Linux run proved the cage compiled and never that it held.

| | what happens today |
|---|---|
| the image ships **no agent CLI** | it installs `git`, `gh`, `ripgrep`, `python3`, `nodejs` — the server's default command is `claude -p …`, so a task dies at the spawn with `command not found` |
| **no cage off macOS** | so no `--dangerously-skip-permissions` ([ADR-0023](adr/0023-os-level-sandboxing.md), D34/D35 — the flag is only safe because the OS is already holding the process), and the CLI denies every write in headless mode |
| **the failure is silent** | measured 2026-08-15 with the cage off: session `completed`, exit 0, task moved to `in_review`, scratch directory empty, and the only "artifact" is the fallback `Run output` — the adapter's JSON envelope, `ttft_ms` and all, handed to a person where a document belongs |
| **the container runs as root** | found 2026-08-16 while measuring the two cage candidates. The `Dockerfile` has no `USER`, and the CLI refuses the flag outright: `--dangerously-skip-permissions cannot be used with root/sudo privileges`, exit 1, *before* authentication. So the cage was never the only thing standing between the image and a working run — a perfect Landlock would have changed nothing, and would have looked like the cause |

- ✅ **CI stops being one Linux box.** ubuntu and macos run the suite (`fail-fast: false`, so a break reports *which* platform); formatting is asked once, clippy everywhere because `cfg`-gated code is only linted where it compiles. Windows is deliberately absent: it is supported *through the image*, and a `cargo test` on a Windows runner would prove a native port we are not doing.
- ✅ **A job that builds the image and proves it works** — not "does it build", but: start the container, create a company, run a knowledge task, and require a **real file** to come out. That is the check that would have caught all three defects at once, and nothing weaker would have caught any of them. Its adapter is a stub, and the script says so: a shell script writes freely, so it is silent on whether the real CLI is permitted to.
- ✅ **A task that produced nothing is not `in_review`.** Independent of any platform, and older than this milestone: `Run output` is a *fallback*, and a fallback that arrives alone means the run delivered nothing. It now fails loudly — session `failed`, task `blocked`, `last_error` quoting whatever the adapter said. Code runs are excluded on purpose: their deliverable is the diff, and one that deliberately changed nothing is a legitimate answer.
- **The cage on Linux** ([ADR-0029](adr/0029-the-cage-inside-the-container.md)). The critical path, not a security nicety: without it the container cannot write, so it cannot work. The two candidates were measured before anything was written, and **neither works on both platforms that matter** — Landlock is absent from Docker Desktop's LinuxKit kernel (`# CONFIG_SECURITY_LANDLOCK is not set`), and `bubblewrap` is blocked by Docker's default seccomp profile unless the user weakens their own container. So the cage is a *set*, chosen by what the platform offers: `available() -> bool` became "which mechanism, if any", while `caged()` stays one predicate and still grants the flag.
  - ✅ **An unprivileged uid, which needs no kernel feature and so works wherever the image does.** The server stays root and drops to uid 10001 per spawn; Overmind's own shelves are `0700`, the database `0600` (WAL and shm too — they carry the same rows), and what merely holds run directories is `0711`, traversable but not listable. Held by paired probes in `container-smoke.sh`: caged, the agent is uid 10001 with the database and every brain **denied**; uncaged, the same probe is root and reads both. Both runs deliver their file, so the boundary is not "the agent could do nothing".
  - ✅ **Landlock as the second layer**, where the kernel offers it — Linux natively and CI, not Docker Desktop. It buys confinement to the run's own directory, which macOS has had since ADR-0023 and the uid alone does not give: runs share a uid, so one can reach another's worktree. Written against the raw ABI rather than a wrapper, because every ergonomic one defaults to **best effort** — enforcing less than you asked for on an older kernel — which turns "the cage is on" into a sentence with no fixed meaning. **Witnessed, not only compiled:** its decidable invariants are tested everywhere (the packed structure's size, the policy growing with the reported ABI and never past it, read-only meaning read-only), and the behavioural pair `a_landlocked_agent_cannot_leave_its_run_directory` **passes on CI's ubuntu runner** — the first machine in the chain with a kernel that has Landlock at all (green on `main` at `48bbe02`, CI run 32043204778, 2026-08-17). Docker Desktop's kernel still has none, so it skips itself there and the uid alone holds the run; on bare-metal Linux Landlock is the *only* mechanism and therefore alone grants the permission flag.
- ✅ **An image someone can actually run.** Not a separate errand: an unprivileged agent with its own `HOME` forces the question of where its credentials live, so ADR-0029 decided it.
  - **An agent CLI in it.** `@anthropic-ai/claude-code`, pinned and overridable at build time — an image that installs "latest" changes under you between two builds of the same commit. Checked for free on every CI run: as the agent uid, unauthenticated, the CLI answers `Not logged in`, which can only be reached by a binary that exists, runs as that uid, **and was allowed the permission flag** — as root the flag is refused first, so this one probe covers the first and fourth defects at once.
  - **Credentials that survive a rebuild.** A named volume on the agent's `~/.claude`, mounted by default rather than as an opt-in nobody discovers. A fresh named volume arrives `root:root`, so the server claims it at startup — measured before and after: `root 0755` → `10001 0700`, and writable by the agent.
  - **Mounts you do not have to guess.** `OVERMIND_REPOS_DIR` (`/repos`) is declared once, and when a workspace path is unreachable the server *says* what it can see: *"cwd '/Users/me/code/my-project' is not a directory. Overmind is running in a container, so a workspace path has to be one it can see. Mounted right now: /repos/another, /repos/my-project."* An empty mount point says that instead, because "nothing is mounted" and "you named the wrong path" need different advice.
  - Verified from inside a real run in the container: `uid=10001`, `home=/home/agent`, the API key reaches the agent process, and its `~/.claude` is writable.
  - **Carried, not closed:** on Linux a mounted repository keeps its host ownership, so a `code` task may not be able to write it — `git` metadata for a worktree lives in the repo, not in the run directory. The answer is `OVERMIND_AGENT_UID`, set to your own `id -u`; the boundary is that the agent is not the *server*, and any unprivileged uid holds it. Documented in `docker-compose.yml`.
- ✅ **Accept, met 2026-08-17.** `docker compose up --build`, a company, a `writer` agent, one knowledge task — and **`ARTIFACT.md`, 229 bytes, written by the real CLI**: as uid 10001, inside the cage, with the permission flag it only gets because the OS is holding it. Session `completed`, exit 0, task `in_review`, and `cost_cents: 19` reaching the agent's ledger against its $50 cap with the reservation released. The whole chain, once, with nothing stubbed.
  - CI carries the half it can, on every change: the image builds, a task reaches an adapter, the deliverable comes back, the cage is proven by paired probes, and the CLI is proven present and permitted without spending anything. What CI cannot carry is authentication, so the real-CLI run is witnessed by hand and recorded here rather than pretended into a job.
  - Landlock is proven by `a_landlocked_agent_cannot_leave_its_run_directory` on the ubuntu runner — the first machine to have a kernel with Landlock at all.
  - **Noted, not a defect of this milestone:** the document was confidently about a *different* Overmind — DarthSim's Procfile process manager. The agent had no company memory configured, so it answered from world knowledge and nothing told it otherwise. The mechanism delivered; the context was empty. That is a fact about running with `OVERMIND_MEMORY_CMD` unset, and an argument for M8's managed brain being on by default in the image.

**Docker is not a substitute for the cage, and the distinction is the whole point.** A container isolates itself from the *host*; the cage isolates the *agent* from Overmind. Inside the image an agent sits next to `overmind.sqlite` and its audit chain, every company's brain, and the per-run MCP token files. The threat model's actual adversary — an agent that misread its task, or a prompt injection inside a document someone handed it — is already inside.

## M20 — How you pay, and what the cap can honestly promise `done`
A subscription and an API key are not two ways to configure the same thing. They are two different economies, and Overmind has been quietly assuming one of them since M6: `budget_cents`, `spent_cents` and the monthly cap are **money**, which is exactly right when you hold an API key and means nothing at all when you hold a subscription. Under a plan there is no dollar to run out of — there is a window, and a quota inside it, and Overmind can see neither.

**Measured first, before designing anything** (2026-08-17, claude 2.1.233):

| | what the CLI will tell us |
|---|---|
| which economy we are in | ✅ `claude auth status --json` → `authMethod`, `apiKeySource`. Free, local, machine-readable. Clean when there is one auth source (`api_key` in the container); ambiguous when there are two (`claude.ai` **and** `apiKeySource` on a host that has both) |
| dollars spent on a run | ✅ already in the envelope, already in the ledger since M18 |
| a hard ceiling inside the adapter | ✅ `--max-budget-usd`, works only with `--print` — which is how we invoke it. Fails recognisably: `subtype: "error_max_budget_usd"`, `terminal_reason: "budget_exhausted"`. **But it overshoots**: a $0.05 cap spent $0.080729, because it stops *after* exceeding rather than pre-authorising |
| quota remaining on a plan | ❌ **nowhere**. The authenticated envelope carries `usage`, `modelUsage`, `service_tier`, `total_cost_usd` and no quota field of any kind. `/usage` exists only inside an interactive session. `auth status` does not carry it |

So the life-line asked for on the API side is buildable and mostly already paid for; the one asked for on the subscription side **cannot be built truthfully**, and the interesting work is deciding what to show instead of a number we would be inventing.

- ✅ **A · The economy is a known fact, not an assumption.** Detected from `claude auth status --json`, held on the server, and reported at `/api/health` — machine-level, because two companies on one server cannot be paying different ways. The startup line says what the cap *means*, not only which economy won: *"paying with: an API key — the budget cap is a ceiling in real money"*.
  - **`authMethod` is not the discriminator**, which is the whole reason this slice was measured before it was written. It answers `claude.ai` both for a key-beside-a-login and for a login alone — the two opposite states — so reading it would have been wrong precisely on a developer's machine, where both credentials usually live. What discriminates is the *presence* of `apiKeySource` and a non-null `subscriptionType`, and the CLI's own precedence rule then falls out rather than being imposed. Held by unit tests built from all three payloads as observed, including one that fails if the two `authMethod` fixtures ever stop agreeing.
  - **Not knowing is a state, not a hole.** A custom `OVERMIND_AGENT_CMD` is never interrogated — `auth status` is not a contract any adapter signed — and an unrecognised shape stays `unknown` with its reason attached, because "unknown" alone sends a person to read source code. `OVERMIND_ECONOMY` declares what you believe when we read it wrong.
  - **The probe runs as the agent, not as the server**, since in the image the server is root and the agent's credentials are not root's. Verified live in the container: with a key it answers `key`, with nothing it answers `unknown — the agent CLI is not signed in`. **Carried:** a key arrives by environment variable, which root and the agent inherit alike, so that scenario does not actually exercise the identity switch. The case it protects — a subscription, whose credentials are files under a home directory — is still unexercised.
- ✅ **B · The cap becomes a ceiling instead of only an estimate.** The remaining budget is passed as `--max-budget-usd`, narrowing M18's stated gap — *"a turn is still not priced before it runs — the estimate is flat, so an agent can overrun by the difference"* — from a whole turn to the adapter's own overshoot.
  - **Server side done, and measured end to end.** An agent capped at 5 cents was handed `--max-budget-usd 0.05`, stopped, and the run reported *"stopped at this agent's budget cap — Reached maximum budget ($0.05). Raise the cap to let it continue."* — session `failed`, task `blocked`. Without recognising the envelope's `error_max_budget_usd` the whole event would have read `agent exited with code 1`, because a ceiling stop carries no `result` field at all.
  - ⚠️ **A coarse brake, not a fine one.** It spent **13 cents against a 5-cent ceiling** — 2.6× — and 1.6× in a bare probe at the same ceiling. The overshoot gets proportionally *worse* as the ceiling shrinks, because a run's fixed context cost does not shrink with it. It will stop a runaway long before a flat estimate would; it will not hold anyone to a number, and the docs say so rather than implying a precision that is not there.
  - **Passed in every economy**, generalising what ADR-0030 first proposed: the cap is also the brake on a looping agent, and a plan's quota is exactly what a loop burns. The ledger still records what was truly spent, so a run can end *over* its cap and the next gate check refuses it — correct, and deliberately not smoothed over.
  - **The run's own reservation is not counted against it.** Subtracting the estimate a run made at checkout would cap every run at the very quantity M18 named as the gap. Held by `a_runs_own_estimate_is_not_subtracted_from_its_ceiling`.
  - ✅ **The life-line itself.** Each agent's bar now reads *"100% rimasto"* — the number a person steers by — instead of two amounts they have to subtract in their head. And it is worded by the economy: the meaning is said **once**, above the chart, rather than repeated beside every agent.
    - under a key: *"Addebitato su una chiave API · Il tetto è un limite in denaro vero."*
    - under a plan: *"Coperto da un abbonamento · Gli importi sono equivalenti, non addebiti — e la quota residua del tuo piano non è visibile da qui."* Amounts wear a `≈` in the tooltip, and the percentage is explicitly of **Overmind's own cap**, never of the plan.
    - when we cannot tell: the cap is shown without a promise attached.
  - Verified in the browser in both economies, in Italian — M16's guarantee holding: the strings went into both dictionaries or the build would have refused them.
- ✅ **C · With a subscription, say what is true — and it turned out more is true than the milestone assumed.** This slice opened intending to show Overmind's own spend with no denominator, because the plan's quota looked unreachable. Pushed to look harder, it is reachable: a headless run emits a **`rate_limit_event`** on `--output-format stream-json --verbose`, carrying which of the plan's clocks is limiting, when it resets, and `allowed` / `allowed_warning` / `blocked` / `rejected`.
  - ✅ **The adapter command moved to `stream-json`** so the plan's state **rides along with work already being done** instead of costing a call of its own — the bargain ADR-0026 made for memory watermarks. The final `result` event is the identical envelope, so cost and failure parsing read exactly what they always did.
  - ✅ **Both clocks, kept apart.** A plan limits on five hours *and* seven days, and a run reports whichever is biting; collapsing them into "the plan" hides the one you are about to hit. Learned separately, shown separately, and a window nobody has reported yet reads **"non ancora riportata"** rather than borrowing the other's state.
  - ✅ **Still no percentage, and that is a fact rather than a shrug.** `used_percentage` exists only in the status line, and a status line is never invoked headless — measured with a probe configured to capture it, which never fired. What is shown instead answers the question a percentage only implies: *"Finestra di 5 ore · vicino al limite · si ricarica tra 2 h"*.
  - ✅ **Exhaustion is now recognisable exactly**, from a status field in the adapter's own closed vocabulary, rather than by matching prose nobody has seen.
  - ✅ **A room whose plan ran out waits, and says a different thing.** M18 built the machinery and left it waiting on exactly this: *"the pause path is where it belongs once we can recognise it reliably."* Recognition is a status field now, so the wiring is small — but the *sentence* is not. Budget-out and plan-out look identical from outside (a room stopped, a person told, a `resume` waiting) and their remedies are opposite: one is "raise the cap", and here **there is no cap**. Its own function and its own notification kind rather than a parameter on the budget one, and the test asserts the note does **not** contain "raise" — telling somebody to lift a limit that is not theirs is worse than saying nothing.
    - The same courtesy in chat: a person who asked a question is told the plan ran out and when it resets, not handed a failure.
    - `allowed_warning` does **not** pause. Stopping work that is still permitted would invert the "transient and external" reasoning that makes pausing right at all.
  - **The correction worth keeping in view:** this milestone's first answer was "the plan's quota is exposed nowhere we can reach", and it was an absence inferred from the two places we happened to look. Reading the adapter's own vocabulary instead of guessing at it turned "no" into two clocks and a countdown.
- ✅ **D · A key must not silently outrank a plan.** The state this exists for is the quiet one: you signed in, the work runs, the plan sits unused, and the bill arrives later. Nothing is broken, which is exactly why nobody notices.

## M23 — Daily use `done`
The owner is about to start using Overmind for real work. Twenty-two milestones were verified by tests, smokes and acceptance runs; none of them was an hour of actually *using* it. So this milestone opens with exactly that — the doctrine applied to ourselves: dogfood first, then fix what actually hurt, in the order it hurt.

**The dogfood (2026-08-21, real key, real work):** a company founded in Italian, its CEO asked for a study-material team, the proposal approved into three hires in one click, a knowledge task that produced a compilable LaTeX exercise sheet (3 pages, first try, 41¢, 131s), and a code task on a mounted repository that added a recipe in house style and judged, correctly, not to touch the README (11¢). - ✅ **A writer waits its turn.** The first minute: a CEO turn was writing its messages, creating a project at the same moment got `database is locked` as a 500. - ✅ **The diff a person reviews survives the uid split.** A code task completed and its diff answered 500: since ADR-0029 the agent commits as uid 10001 while the server asks git questions as root, and git refuses a repository owned by another user — *dubious ownership*. Every code task in the image was unreviewable, and the smoke stayed green because it had never run a code task. The server's git helper now declares the one path it chose to operate on safe, per invocation — exact, not `*` — measured in the container before written. The smoke now runs a code task in both scenarios and demands the diff endpoint answer with the change in it; on CI's Linux runner the mounted repo keeps the runner's uid, so the new leg bites hardest exactly where the defect lived.
- ✅ **The toolchain is yours to extend.** Asked for a LaTeX sheet, the agent ran `pdflatex` to verify its own deliverable — command not found — and shipped anyway, honestly, with the failure logged beside the file. Baking every toolchain in would grow the image without bound; `EXTRA_APT_PACKAGES` at build time adds what your agents need, documented where the choice is made. Both branches verified: empty builds identically, a named package installs and runs.
- ✅ **A subscription survives the cage.** The owner asked, in so many words, whether paying with his plan works — and it did not: on macOS a subscription's OAuth token lives in the **login Keychain**, which the cage denies, so every plan-paid run died at exit 1 with an empty stderr while every key-paid one sailed through (a key rides the environment). The profile now grants `~/Library/Keychains` and `~/Library/Preferences` **read-only, never writable** — the file, not the secrets: items stay encrypted and securityd enforces per-item ACLs either way. ## M24 — The door (authentication) `done`
Designed in [ADR-0032](adr/0032-authentication-the-boundary-moves-off-the-machine.md), deliberately before any code: the owner asked for authentication done *properly*, and security code written at the end of a long day is how doors get hinges on the outside. The boundary moves off the machine and onto a credential: one owner account claimed atomically on first run, argon2id passwords, server-side sessions stored hashed, HttpOnly/SameSite cookies, everything guarded but the door itself, login rate-limited and audited with an `actor` that every audit event carries from here on. - ✅ **Slice A — the door stands.** Migration (`users`, `auth_sessions` storing only token hashes), argon2id with a per-password salt, the atomic first-run claim (of six racing claims exactly one wins — tested), sessions minted from 256 OS bits, the wall on every `/api` route with the three exceptions the ADR names (the door, a health redacted to liveness, the SPA's own bytes), the WebSocket behind the same wall, login rate-limited **per attempted name** — per-IP on a loopback server is theater — with the same wordless 401 for a wrong name and a wrong password over a dummy-hash verify, so timing tells no names.   - Found on the way: a middleware layered on the nested `/api` router sees **prefix-stripped paths** — matching `/api/auth` let nobody log in, and only the door suite caught it.
- ✅ **Slice B — the belt, the actor, the exit, and the model told true.** The CSRF content-type contract on top of `SameSite=Strict` (a bodied mutation declares JSON or multipart, shapes a forger cannot send with credentials). The `actor` on **every** event an authenticated request appends — injected by the wall through a task-local and riding *inside the hashed payload*, because a column would either sit outside the chain or change the hash formula under every existing chain; background tasks stay the system's own, and a failed login records the attempted name under a different key, because a target is not an actor. A sign-out control in the top bar; a session that dies under the app sends you back to the door (the client announces every 401 once). The threat model rewritten around the credential — the door guards the port, **nothing guards a hostile host** — with seven new rows in the held-by table, each naming its test; its guard-test updated deliberately, exactly as its own comment instructed. `tests/the_door.rs` grows to ten. 192 tests, clippy clean.

A taken name refuses in the same wordless shape as a failed login: whether a name exists is not for an anonymous caller to enumerate. Registration is open to whoever reaches the port, and the threat model says so out loud — the port being loopback or a tunnel of your own machines. Walked live: landing → sign-up → back → login → back → sign-up → in, by accessible names. `the_door.rs` grows to twelve.

## M25 — Several people, one company `in-progress`

## M26 — The price of a turn, learned `done`
Two milestones carried the same sentence: *"a turn is still not priced before it runs — the estimate is flat."* Since M6 every checkout reserves fifty cents for every agent, every model, every kind of work; M20 measured the adapter's own brake at 2.6× overshoot on a five-cent ceiling. The flat number is wrong in both directions — a three-cent writer is refused at a ten-cent cap because fifty does not fit, a dollar-a-run reviewer is waved through at sixty because fifty does — and the ledger has held the truth since M18: one `cost_event` per invocation, per agent. [ADR-0035](adr/0035-the-estimate-learns-from-the-ledger.md).

- ✅ **Slice A — the estimate learns.** At checkout, task or turn, the reservation is the 75th percentile of the agent's last ten costs *of the same kind* (task runs summed per session, turns one per event) — above the median on purpose, because a reservation exists to keep the next run inside the cap. Fewer than three samples and the flat number stands, visibly (`samples: 0`). The ceiling `--max-budget-usd` is untouched: what the gate reserves and what the adapter enforces stay two layers.
- ✅ **Slice B — what is reserved is said.** The budget summary carries each agent's next-task and next-turn estimate with its sample count; the life-line says *"≈ 3¢ a turn, from 8 turns"* so the person steering by the bar knows whether the number is the agent's or the default's.
- ✅ **Accept.** A three-cent agent at a ten-cent cap starts (it used to be refused on the flat guess); a ninety-cent agent at a sixty-cent cap is held (the flat guess would have let it through); one data point is not a price. Held by `the_price_of_a_turn.rs` plus two unit tests on the percentile. Walked live with a stub agent: three two-cent runs → `task: {cents: 2, samples: 3}`, `turn: {cents: 50, samples: 0}`, and the org view reads *prossimo: ≈0,02 € a task · ≈0,50 € a turno*. M18's carried sentence is retired. 211 tests, clippy clean.

## M27 — Release 0.1 `done`
Twenty-six milestones closed by tests and live acceptance, a README and a site that say what the product is, and a badge that still reads *pre-alpha*. The product is whole enough for a first public release; what is missing is the release itself — the things a stranger needs to try it from a link and to tell us what broke.

- ✅ **Slice A — a CI that does not flake.** A release with a CI that sometimes fails is a release nobody can trust a red build of. The one known flake — `two_overlapping_runs_writing_the_same_thing_are_reported` on the macOS runner — is the test's memory stub racing itself: Overmind's memory pool runs two stores concurrently, and two stub processes that each read the file before the other appended saw neither the other's row nor the collision. The stub now serializes stores with a file lock, as a real provider does. **And the second cause, found when the first fix did not hold on CI:** the session is marked complete *before* the memory is stored and the collision reported — memory is best-effort and comes after, by design — so the notification is eventual, and the test read the inbox once, immediately. It now waits for it the way a person would. **And a third, not a flake but a bug the flakes were hiding:** two concurrent `code` runs on the same repository raced inside `git worktree add` — *"failed to read .git/worktrees/<other session>/commondir"*, the second add reading the first's half-written entry — and git offers no lock of its own. The runner now takes one lock per repository around the add; runs on different repositories never wait on each other. Held by `concurrent_tasks_use_memory_in_parallel`, which is where it bit.
- ✅ **Slice B — a version, a changelog, a release.** `CHANGELOG.md` written from the milestones, the workspace version at `0.1.0`, a `v0.1.0` tag and a GitHub Release whose notes are the changelog's first entry.

## M31 — Backup and restore `done`
Opened 29 Aug 2026 from the second friction of the two-machine walk and the third item of *Where 0.1 leaves us*: **the data has no way out.** Designed in [ADR-0044](adr/0044-the-archive-is-the-instance.md) before any code — the owner's decisions (the token sealed by a passphrase, download *and* a folder on the server, everything durable, restore on an empty instance only) are the shape; the first draft of the ADR went through `/code-review` and came back with sixteen verified defects (secrets left unsealed in the database, the endpoints open on an unclaimed instance, a swap under a live WAL pool, the database path assumed under `/data`, a 128 MB body limit, an irreversible swap on a wrong passphrase), all of which the accepted design answers.

- ✅ **Slice A — the archive, and the threat-model row with it** (29 Aug 2026, `tests/backup.rs`, eight behaviours; found on the way: sqlx's in-memory database answers `VACUUM INTO` with success and no file, an `UPDATE` on the snapshot left the scrubbed token readable in page slack until `secure_delete` + `VACUUM`, and `/security-review` caught two more before the merge — a staging tree at the umask's `0755` inside a deliberately traversable data dir, and `meetings/` copied as the server out of a directory the agent owns). `POST /api/backup` (owner only, claimed instance only): a `tar.gz` assembled from staging with a manifest first — a hash per entry, the chain report of the *snapshot*, the database taken with `VACUUM INTO` from the `OVERMIND_DB` path with `mcp_token` and `company_tokens.token` scrubbed, each Wadachi brain the same way, the token sealed with argon2id (m=64 MiB, t=3, p=1) + XChaCha20-Poly1305 under a passphrase the server never keeps. `OVERMIND_BACKUP_DIR` (default `<data>/backups/`, `0700`/`0600`, the smoke probe extended), streamed by `GET /api/backup/<name>` with `<name>` a bare entry of the folder, listed by `GET /api/backups`; `backup.exported` on the chain with the actor. The threat-model row lands in this slice, held by tests that read the archive bytes.
- ✅ **Slice B — the restore** (30 Aug 2026, `tests/restore.rs`, eleven behaviours: a real archive out of one instance and into another, the chain verified on the way in, the swap driven by hand the way a boot drives it). Found on the way: the door answers a stranger before the emptiness check can, which is right — a claimed instance says `401` to nobody-in-particular and `409` with the way out to its owner; and `audit_events` is append-only by trigger, so the test that proves a broken chain is caught has to drop the trigger first, exactly as somebody holding the file would. `POST /api/restore`, accepted only on an *empty* instance (no user, no company, no token — its own predicate), streamed to staging and exempt from the body limit: manifest format and version checked, every hash checked, the chain verified against the manifest's report, the token unsealed — a wrong passphrase refuses the whole restore while a retry is still free; `skip_token` restores without the token and without `pay-with-plan`. Then `restore-pending`, the answer, exit 0; **the swap happens at boot before the pool opens** (stale `-wal`/`-shm` removed, `backup.restored` appended as a system event). A non-empty instance answers `409` with what makes it so and the way out.
- ✅ **Slice C — the UI and the words** (31 Aug 2026). An `Archive` icon beside Invite in the top bar, owner only: export (a passphrase field that appears only when a sign-in would seal into it — the listing says so, so the field is never shown for nothing), the kept archives with size, date, download and an audited delete. On the door's unclaimed landing, *Restoring from an archive instead?* opens a file picker; the first attempt against the server is what learns whether the archive is sealed, and the passphrase field (or *restore without the sign-in*) appears only then. The compose's volume comment now names the verb; the wiki page was written on 1 Sep 2026 — `/wiki/backup`, in the site's own repository, which also carries what only the raw volume copy still holds: the agent CLI's own login, and only when it was made from the shell with `claude setup-token` rather than from the product. It is committed there and goes live with the site's next deploy, which is the owner's to run.
- ✅ **Accepted 1 Sep 2026, on the owner's own instance.** The owner exported the house instance from the product (Archive → passphrase → Export); the archive — **261 MB, 321 entries, a chain of 920 events** — was restored into a **fresh container** built from `main`, which staged it, stopped, and **came back on its own in two seconds** under the compose file's `restart: unless-stopped`, swapping at boot before the database was opened. Row for row against the source: 2 companies, 19 agents, 100 tasks, 134 messages, 2 conversations, 1 meeting turn — all identical; on disk 188 artifacts and 74 attachments, all of them; `pay-with-plan` present. The restored chain holds the archive's 920 events with `backup.restored` appended, while the source's 921st is the `backup.exported` written after the snapshot was taken — the two differ by exactly the two events that should differ. The six brain files not in the archive are `brain.db-wal`, `brain.db-shm` and `brain.db.migrate.lock` per company, excluded on purpose. ## M32 — The install is one script, and an unclaimed instance is not open `in-progress`
Opened 1 Sep 2026 in [ADR-0045](adr/0045-the-install-is-one-script.md), from the first friction of the two-machine walk — the container engine was never covered — and from a hole the ADR's own review widened: *"claim it before anybody else does"* was advice, not a mechanism. The ADR named two problems. There were **six**.

- ✅ **Slice A — the door** (2 Sep 2026, PR #89). (1) The claim cost nothing: whoever reached the port owned the instance. (2) `auth::wall` waved the whole API through while `users` was empty — and founding a company starts a task, which runs an agent CLI on the host; so did `/economy/pay-with`, `/claude-auth/*`, `/auth/invites` and a restore. (3) **`signup` made whoever signed up the owner**, with neither invite nor code — and `authClaim` was called nowhere in the UI, so the product's own door used that path. (4) `ws_wall` kept the same exception, and a socket is authorised once, at the upgrade, never again, with no per-company filtering. (5) The code **failed open** three ways: a boot that could not write it logged a line and served anyway, `stored_setup_code` swallowed every I/O error into the same `None` as "absent", and `setup_code_ok` read that `None` as yes. (6) The web restore never sent the code, so that flow was dead from the product.
  Now: a code minted at first boot into `<data>/setup-code` (`0600`, Crockford's alphabet minus the ambiguous letters, constant-time compare, written whole by rename, spent by the claim); the wall closed; signup refused while nobody owns the instance; `/restore` reachable only while unowned and demanding the code **before a byte reaches disk**; and a boot that cannot mint **refuses to serve**. ~130 tests across 30 suites had never needed a session — they claim now, through one shared helper that signs in instead of claiming when the instance is already owned. Three rows in the [threat model](THREAT-MODEL.md), and two of its claims corrected: *"an unclaimed instance is exactly as open as before M24"* was a promise written as a design choice, and *"a caller without a session gets nothing, **once an owner exists**"* — that trailing clause **was** the hole, stated in the document meant to disclose it.
- ✅ **Slice B — the script** (3 Sep 2026, in PR #91). `scripts/install.sh` and `scripts/install.ps1`: seven steps, no eighth. It asks the **engine** whether it is there rather than the filesystem (`docker info`, because "installed but not started" and "not in the docker group" both pass `command -v docker` and fail later and worse), and never installs anything itself. The folder it makes is the installation ([ADR-0047](adr/0047-the-folder-is-the-installation.md)). It takes the compose file from **its own release, by tag, against a digest stamped into it** — and that guard tests the *shape* of the values, never the sentinel: written as a comparison against the placeholder, the release step's `sed …|g` rewrote the guard too, leaving a value compared with itself and the whole check skipped. An unstamped script now refuses rather than downloading unverified. The body is a function called on the last line, so a truncated download runs nothing; the published port is read from the compose file rather than assumed; and the setup code is printed in the terminal the person is already looking at, which is the step this exists to remove.
- **Slice C — the graphical road, free** (not started). Signing was priced and rejected on the owner's word ($99/yr Apple, $9.99/mo Azure, $280+/yr EV): an unsigned `.pkg` greets a person with the warning reserved for malware. The free candidates are written down in the ADR rather than chosen — a Homebrew cask and a `winget`/Scoop manifest, a double-clickable wrapper of the same script, the home-server app stores. The Docker Desktop extension is out: Extensions ship **disabled by default** since August 2026, so nobody would find it.
- **Accept:** on a machine with no Overmind, one line installs it and prints the code; the claim is refused without that code and taken with it; an instance nobody has claimed answers about its door and nothing else — no company founded, no task started, no invite minted, no socket opened; and the same line, run again, updates without touching the data.
